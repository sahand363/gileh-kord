> **سامانه جامع مدیریت خرید، تدارکات، درآمد، کارکرد کارکنان و عملیات رستوران**
>
> یک سامانه مدرن، سازگار با موبایل، آماده برای کار در حالت آفلاین و توسعه‌یافته با استفاده از Svelte، TypeScript، Vite و IndexedDB که مدیریت خریدها، درآمد و کارکنان رستوران را یکپارچه می‌کند.

## ⚡ نصب سریع (با یک دستور در اوبونتو)

با اجرای تنها یک دستور، کل برنامه شامل محیط اجرای Node.js، ساخت نسخه نهایی، سرویس systemd و پراکسی معکوس Nginx را روی سرور اوبونتو نصب و راه‌اندازی کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/sahand363/gileh-kord/main/install.sh -o install.sh && sudo bash install.sh
```

یا با اجرای مستقیم دستور از طریق Bash:

```bash
sudo bash <(curl -fsSL https://raw.githubusercontent.com/sahand363/gileh-kord/main/install.sh)
```

> **نکته:** پس از نصب، برای دسترسی به منوی مدیریتی تعاملی، در هر زمان دستور زیر را اجرا کنید:

```bash
sudo gk
```

## 🌟 قابلیت‌های اصلی

- **طراحی مینیمال و بهینه‌شده برای موبایل:** رابط کاربری به‌گونه‌ای طراحی شده که در محیط‌های شلوغ آشپزخانه و انبار، امکان کار سریع و آسان با یک دست را فراهم کند. همچنین از نمایشگرهای دسکتاپ به‌صورت واکنش‌گرا پشتیبانی می‌کند.

- **سازگاری کامل با HTTP و HTTPS:** برنامه هم از طریق IP عمومی سرور و اتصال HTTP (`http://SERVER_IP`) و هم از طریق دامنه امن HTTPS (`https://gilehkord.modesehramiz.ir`) به‌طور کامل قابل استفاده است. قابلیت‌های اصلی برنامه هیچ وابستگی‌ای به HTTPS ندارند.

- **موتور تولید شناسه UUID سه‌لایه و مقاوم:** تولید شناسه‌های منحصربه‌فرد و ایمن در محیط‌های مرورگری امن و غیرامن، بدون اتکای صرف به `crypto.randomUUID()`.

- **پشتیبانی کامل از تقویم شمسی:** تقویم داخلی فارسی با چیدمان راست‌چین (RTL)، انتخاب تاریخ، تبدیل روزهای هفته، محاسبه سال‌های کبیسه و فیلتر بازه‌های زمانی با استفاده از کتابخانه `jalaali-js`.

- **ثبت و حفظ خودکار مسئول خرید:** آخرین مسئول خرید انتخاب‌شده به‌صورت خودکار برای ثبت خریدهای بعدی حفظ می‌شود. امکان ویرایش مستقیم اطلاعات و پشتیبانی از خریدهای قدیمی بدون مسئول مشخص نیز وجود دارد.

- **محاسبه سهم کارکنان بر اساس کارکرد واقعی:** توزیع متناسب درآمد بر اساس حاصل‌ضرب ساعات کارکرد واقعی هر کارمند در ضریب عملکرد اختصاصی او. برای مثال، ۱۰ ساعت کار با ضریب ۰٫۶ معادل ۶ ساعت کار مؤثر خواهد بود.

- **حفظ محرمانگی درآمد در بخش عمومی:** در صفحات عمومی، تنها مبلغ محاسبه‌شده بر اساس ضریب تعیین‌شده توسط مدیر (پیش‌فرض ۰٫۶ و قابل تنظیم) نمایش داده می‌شود و رقم واقعی فروش در دسترس کاربران عمومی قرار نمی‌گیرد.

- **نمودارهای ستونی عمودی:** نمایش ساده و سبک نمودارهای ستونی برای بررسی درآمد روزانه و ماهانه، تراز مالی و نحوه توزیع سهم کارکنان.

- **هشدار اختیاری کمبود موجودی برای هر کالا:** امکان فعال یا غیرفعال کردن هشدار کمبود موجودی به‌صورت جداگانه برای هر قلم کالا از طریق چک‌باکس اختصاصی.

- **بخش مدیریتی محافظت‌شده:** دسترسی متمرکز و محافظت‌شده با استفاده از اطلاعات ورود اصلی سرور SSH (`ADMIN_USER` / `ADMIN_PASS`) همراه با سازوکار جایگزین برای شرایط آفلاین.

- **پشتیبان‌گیری و بازیابی اتمیک از ۹ مخزن داده:** امکان خروجی گرفتن کامل از اطلاعات در قالب JSON و بازیابی یکپارچه و اعتبارسنجی‌شده اطلاعات در تمام مخازن پایگاه داده.

## 🔐 حریم خصوصی و مدل توزیع درآمد

### ۱. محدوده حفظ حریم خصوصی در بخش عمومی

- در صفحات عمومی شامل «ثبت خرید»، «درآمد» و «پیشخوان»، ارقام واقعی درآمد و فروش نمایش داده نمی‌شوند.
- مبلغ نمایش‌داده‌شده در بخش عمومی درآمد، صرفاً بر اساس ضریب تعیین‌شده توسط مدیر (پیش‌فرض `0.6`) محاسبه می‌شود و با عنوان ساده **«درآمد»** نمایش داده خواهد شد.
- در قسمت پایین صفحه عمومی «درآمد»، فقط تاریخ آخرین ثبت‌ها نمایش داده می‌شود و هیچ‌گونه مبلغ یا مجموع مالی در این قسمت قابل مشاهده نیست.

### ۲. محاسبه سهم کارکنان به‌صورت متناسب با کارکرد

سهم هر کارمند به‌صورت پویا و بر اساس ضریب اختصاصی او محاسبه می‌شود:

$$\text{ساعات کار مؤثر} = \text{ساعات کارکرد واقعی} \times \text{ضریب کارمند}$$

$$\text{سهم تخصیص‌یافته} = \text{کل درآمد} \times \left( \frac{\text{ساعات کار مؤثر کارمند}}{\sum \text{ساعات کار مؤثر تمام کارکنان}} \right)$$

**مثال:** اگر کارمندی ۱۰ ساعت کار کرده باشد و ضریب عملکرد او `0.6` باشد، کارکرد مؤثر او معادل ۶ ساعت محاسبه می‌شود. در نتیجه، درآمد بر اساس نسبت ساعات کار مؤثر بین کارکنان توزیع خواهد شد.

### ۳. ضریب نمایشی درآمد برای مدیر

مدیر می‌تواند از طریق **پنل مدیریت** ضریب نمایش درآمد در بخش عمومی را تغییر دهد. مقدار پیش‌فرض این ضریب `0.6` است، اما می‌توان آن را به هر مقدار دلخواه، مانند `0.5`، `0.75` یا `1.0` تغییر داد.

سیستم درآمد واقعی را در این ضریب ضرب کرده و حاصل را در داشبوردها و صفحات عمومی نمایش می‌دهد.

| بخش | فناوری |
| --- | --- |
| **فریم‌ورک اصلی** | [Svelte 4](https://svelte.dev/) + [TypeScript](https://www.typescriptlang.org/) |

| **مدیریت فرایندها** | Linux systemd (`gileh-kord.service`) |
| **ابزارهای تست** | [Vitest](https://vitest.dev/) + [fake-indexeddb](https://github.com/dumbmatter/fake-indexeddb) |

- Node.js نسخه ۱۸ یا بالاتر (نسخه ۲۰ LTS پیشنهاد می‌شود).
- npm نسخه ۹ یا بالاتر.

git clone https://github.com/sahand363/gileh-kord.git

## 🚀 نصب و مدیریت روی سرور اوبونتو

### ابزار مدیریت خط فرمان `gk`

اسکریپت نصب، ابزار مدیریتی `gk` را در مسیر `/usr/local/bin/gk` قرار می‌دهد.

برای دسترسی به منوی مدیریت، دستور زیر را در ترمینال اوبونتو اجرا کنید:

```bash
sudo gk
```

منوی مدیریت به شکل زیر خواهد بود:

```text
==============================================================
   GILEH KORD - SSH Deployment, Master Auth & SSL Manager
==============================================================
  App Status  : RUNNING
  HTTP IP URL : http://94.184.6.138
  Domain URL  : https://gilehkord.modesehramiz.ir
  Master User : admin (Configure in Option 8)
  Shortcut    : sudo gk
--------------------------------------------------------------
   1) نصب گیله‌کُرد (راه‌اندازی خودکار سریع)
   2) به‌روزرسانی برنامه از GitHub
   3) اجرای برنامه
   4) متوقف کردن برنامه
   5) راه‌اندازی مجدد برنامه
   6) بررسی وضعیت برنامه
   7) مشاهده گزارش‌ها و لاگ‌های برنامه
   8) تنظیم نام کاربری و رمز عبور مدیر اصلی، دامنه و پورت
   9) راه‌اندازی / دریافت گواهی SSL رایگان Let's Encrypt (اختیاری)
  10) بررسی وضعیت SSL و آزمایش تمدید گواهی
  11) ساخت مجدد بخش Frontend
  12) حذف کامل برنامه
  13) خروج
==============================================================
```

### تنظیم نام کاربری و رمز عبور مدیر اصلی

۱. با اجرای دستور `sudo gk` منوی مدیریت را باز کنید.

۲. گزینه **۸** با عنوان `Configure Master Username/Password, Domain & Port` را انتخاب کنید.

۳. نام کاربری اختصاصی مدیر اصلی (`ADMIN_USER`) و رمز عبور آن (`ADMIN_PASS`) را تنظیم کنید.

۴. اطلاعات در مسیر امن زیر ذخیره می‌شوند:

```text
/etc/gileh-kord/config.env
```

اعتبارسنجی اطلاعات ورود نیز از طریق مسیر زیر انجام می‌شود:

```text
POST /api/auth/login
```

## 🌐 دسترسی دوگانه از طریق HTTP و HTTPS اختیاری

گیله‌کُرد از معماری دوگانه Server Block در Nginx استفاده می‌کند:

### ۱. دسترسی از طریق IP و HTTP

```text
http://SERVER_IP
```

- همیشه روی پورت ۸۰ فعال است.
- هیچ‌گاه کاربر را به HTTPS هدایت اجباری نمی‌کند.
- حتی بدون داشتن دامنه، امکان دسترسی کامل به برنامه وجود دارد.

### ۲. دسترسی از طریق دامنه و HTTPS

```text
https://gilehkord.modesehramiz.ir
```

- راه‌اندازی آن اختیاری است.
- ارتباط امن HTTPS را فراهم می‌کند.
- امکان نصب برنامه به‌صورت PWA را فراهم می‌سازد.
- دسترسی مستقیم از طریق IP را مختل نمی‌کند.

### راه‌اندازی SSL رایگان با Let's Encrypt

**۱.** در پنل مدیریت ارائه‌دهنده DNS دامنه خود، یک رکورد از نوع **A Record** ایجاد کنید:

- **Host:** `gilehkord`
- **Points to:** آدرس IP عمومی سرور شما

**۲.** پس از انتشار و اعمال تنظیمات DNS، دستور `sudo gk` را اجرا کرده و گزینه **۹** با عنوان `Setup / Issue Free Let's Encrypt SSL` را انتخاب کنید.

**۳.** ابزار Certbot از طریق روش Webroot گواهی SSL را دریافت می‌کند و تنظیمات تمدید خودکار گواهی نیز از طریق `certbot.timer` انجام می‌شود.

## 📦 مشخصات پایگاه داده و پشتیبان‌گیری

پایگاه داده سمت کاربر مبتنی بر IndexedDB با نام `gileh_kord_db` و نسخه ۴، شامل ۱۰ مخزن داده (Object Store) است:

| نام مخزن | کلید اصلی | توضیحات |
| --- | --- | --- |
| `purchases` | `id` (`purch_*`) | اطلاعات خریدها به همراه مسئول خرید، تعداد و قیمت |
| `products` | `id` (`prod_*`) | فهرست کالاها، آخرین قیمت خرید و واحدهای پیش‌فرض |
| `employees` | `id` (`emp_*`) | پروفایل کارکنان، سمت شغلی، برنامه کاری و ضرایب عملکرد |
| `timesheets` | `id` (`ts_*`) | سوابق حضور و غیاب، ورود و خروج و شیفت‌های شبانه |
| `revenues` | `id` (`rev_*`) | سوابق فروش روزانه در دو حالت ثبت مبلغ کلی یا ثبت جزئیات اقلام |
| `expenses` | `id` (`exp_*`) | هزینه‌های جاری مانند قبوض، اجاره و تعمیر و نگهداری |
| `inventory` | `id` (`inv_*`) | اطلاعات موجودی انبار و تنظیمات اختیاری هشدار کمبود کالا |
| `suppliers` | `id` (`sup_*`) | فهرست تأمین‌کنندگان و مجموع حجم خرید از هرکدام |
| `manager_auth` | `key` | حافظه احراز هویت مدیر اصلی و اطلاعات مشتق‌شده از اعتبارنامه‌ها |
| `settings` | `key` | تنظیمات محلی، شناسه مسئول خرید ذخیره‌شده و ضرایب |

### پشتیبان‌گیری JSON و بازیابی اتمیک

- **فرمت فایل:** ساختار JSON اعتبارسنجی‌شده با نسخه `version: 3`.
- **عملیات اتمیک:** بازیابی اطلاعات در قالب یک تراکنش واحد و چندمخزنی روی تمام ۹ مخزن داده انجام می‌شود.
- **حفظ اطلاعات قبلی:** اگر اعتبارسنجی فایل پشتیبان با شکست مواجه شود، اطلاعات موجود در پایگاه داده بدون تغییر باقی می‌مانند.

## 📋 راهنمای بررسی عملکرد در حالت آفلاین

۱. **بررسی عملکرد HTTP:** آدرس `http://SERVER_IP` را در مرورگر باز کنید. یک خرید ثبت کرده و پس از بارگذاری مجدد صفحه، از ذخیره شدن اطلاعات اطمینان حاصل کنید.

۲. **بررسی ثبت مسئول خرید:** مسئول خرید انتخاب‌شده را در فرم تغییر دهید. مشاهده خواهید کرد که انتخاب انجام‌شده برای ثبت‌های بعدی نیز حفظ می‌شود.

۳. **ویرایش اطلاعات خرید:** روی گزینه **«ویرایش»** در کارت هر خرید کلیک کنید تا مشخصات کالا، قیمت یا تاریخ خرید را مستقیماً تغییر دهید.

۴. **بررسی پایداری در حالت آفلاین:** پس از بارگذاری کامل برنامه، اتصال اینترنت را قطع کنید. خریدهای جدید ثبت کنید، تایم‌شیت کارکنان را تکمیل کنید و درآمد روزانه را وارد کنید. تمام اطلاعات در IndexedDB ذخیره شده و بلافاصله در برنامه نمایش داده می‌شوند.

۵. **بررسی دسترسی مدیر:** با استفاده از اطلاعات ورود SSH، وارد **پنل مدیریت** شوید. نمودارهای ستونی درآمد واقعی، ضرایب کارکنان و نحوه توزیع متناسب سهم‌ها را بررسی کنید.
